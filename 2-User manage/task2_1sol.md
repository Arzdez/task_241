# Управление пользователями

### 1. Добавить пользователей user1 и user2, установить им пароли.

```shell
sudo useradd -m -s /bin/bash user1
sudo useradd -m -s /bin/sh user2
sudo passwd user1
sudo passwd user2
```

### 2. Создать группу labusers. Добавить user1 в администраторы. Добавить user1 и user2 в labusers.

```shell
sudo groupadd labusers
sudo usermod -aG sudo user1
sudo usermod -aG labusers user1 user2
```

### 3. Что такое права доступа? Вывести права доступа на файлы в домашней директории одного из пользователей.

Права доступа определяют, кто может читать, изменять или запускать файл. Они делятся на три группы: владелец, группа, остальные.

```shell
ls -la /home/user1
```

### 4. Создать файл, доступный на чтение всем, а на запись только владельцу.

```shell
echo "тестовый файл" > lab2/shared.txt
chmod 644 lab2/shared.txt
```

#### 4.1) Временно выставить права 777.

```shell
chmod 777 lab2/shared.txt
```

#### 4.2) Почему такая настройка обычно избыточна?

Права 777 дают всем пользователям полный доступ: чтение, запись и выполнение. Это опасно, потому что любой пользователь в системе может изменить или удалить файл. Обычно достаточно дать чтение всем и запись только владельцу.

#### 4.3) Вернуть минимально необходимые права.

```shell
chmod 644 lab2/shared.txt
```

### 5. Как называется встроенная учётная запись администратора в Linux?

Встроенная учётная запись администратора называется **root**.

### 6. Как выполнить одну команду с административными правами?

Перед командой нужно написать `sudo`:

```shell
sudo ls /root
```

### 7. Есть ли у суперпользователя абсолютная возможность выполнить любую операцию?

Нет, не всегда. Например, root не может записать данные в файловую систему, смонтированную в режиме read-only, или удалить файл с установленным immutable-атрибутом (флаг `i`, задаётся через `chattr +i`). Также ограничения могут накладывать механизмы вроде AppArmor или SELinux.

### 8. Удалить пользователя user2, сохранив его домашний каталог. Показать, что пользователь удалён.

```shell
sudo userdel --preserve-home user2
grep user2 /etc/passwd
```

### 9. Изменить владельца и группу файла. Изменить владельца файла из пункта 4.

```shell
sudo chown user1:labusers lab2/shared.txt
```

### 10. Показать UID, основной GID и дополнительные группы user1.

```shell
id user1
```


### Краткое пояснение назначения r, w, x для файла и каталога

**Для файла:**
- `r` (read) — право читать содержимое файла.
- `w` (write) — право изменять содержимое файла.
- `x` (execute) — право запускать файл как программу или скрипт.

**Для каталога:**
- `r` — право просматривать список файлов в каталоге.
- `w` — право создавать, удалять и переименовывать файлы внутри каталога.
- `x` — право переходить в каталог (входить в него) и обращаться к файлам внутри, если известно их имя.
